# Financial schema fingerprint gate

`schema_fingerprint.sql` is read-only. It hashes definitions and privileges for every `public`/`private` relation, column, constraint, index, non-internal trigger, policy, function, enum/domain, and database extension. It never selects application table rows. The checked-in `deployed_schema_fingerprint_20261024.json` was obtained through the already-authorized Supabase read-only SQL connector from the PlaySpot target on 24 October 2026. It contains object names and MD5 fingerprints, no function bodies, customer rows, passwords or payment records.

The probe observed 3,607 objects on Postgres major 17, including 23 non-internal `bookings` triggers and the `payments_booking_id_unique` constraint. On 25 October 2026, a schema-only CLI export (SHA-256 `08D6C1D70278DA715A5AF80BC3A832358D098F9DD72EB1B6C2F56935ED5293CA`) restored in a fresh isolated Supabase PostgreSQL 17.11 container; after reconciling local default/column ACLs and two PostGIS-owned security triggers, this probe matched 3,607/3,607 target objects. The export and reconciliation scripts are kept outside Git. Matching the fingerprint does **not** prove financial behavior or all Auth internals, and the target can drift after capture.

To compare an authorized schema-only restore, run the probe against the isolated database with `psql -XAt -v ON_ERROR_STOP=1 -f supabase/tests/financial_contract/schema_fingerprint.sql > restored.json`, then `node supabase/tests/financial_contract/compare_schema_fingerprints.mjs supabase/tests/financial_contract/deployed_schema_fingerprint_20261024.json restored.json`. Exit code 0 means names and hashes match; exit code 1 lists missing, extra and changed objects. `node --test supabase/tests/financial_contract/compare_schema_fingerprints.test.mjs` verifies the comparison logic.

Acquire the schema with Supabase CLI's **schema-only** `db dump` from a separately authorized connection, or use a verified disposable Supabase branch without customer data. Restore into an isolated Postgres 17 environment with matching extensions and role scaffolding. Never use `--data-only`, copy customer rows, commit a connection string, or apply DDL to the target. The current project cannot create a Supabase development branch on its plan. The successful local restore found that `pg_dump` explicit grants alone do not cancel broader privileges inherited from a fresh local Supabase image. Normalize isolated ACLs from the read-only target catalog and recreate extension-owned triggers before accepting a match. See the dated audit for the exact restored-schema financial reproductions and remaining gates.

# Open Time partial-payment status — isolated exact-schema regression

**Scope:** a narrow correction to `public.complete_booking_session` on a Draft branch targeting `dev`. No production database change, money movement, deployment or merge occurred.

The deployed function returned and stored `unpaid` whenever a completed session had any balance due, even when `payments` recorded a positive completed collection. A disposable Supabase PostgreSQL 17.11 container restored the authorized schema-only export from the PostgreSQL 17.6 target. The export SHA-256 is `08D6C1D70278DA715A5AF80BC3A832358D098F9DD72EB1B6C2F56935ED5293CA`. After reconciling local default/column ACLs and two PostGIS-owned security triggers, 3,607/3,607 public/private fingerprint objects matched. No customer rows were exported.

The synthetic baseline reproduced an Open Time booking at 100.00 with 40.00 genuinely recorded in both payment and shift ledgers. Closing returned `final_total=100.00`, `amount_paid=40.00`, `amount_due=60.00`, but `payment_status=unpaid`. The committed regression script also failed against the original deployed function: at 64 elapsed minutes, 15-minute rounding and rate 100/hour, the authoritative total was 125.00 with 40.00 paid and 85.00 due, yet status was `unpaid`.

The migration preserves the exact deployed function body except for classifying positive partial collections as `partial` in Open Time, fixed-session and idempotent-close paths. The precondition hash `b981afd7650dcc530867b69bdd80f0e9` was verified both on the deployed target and on the matched restore. A definition hash guard refuses an unrecognized function, while allowing safe repeat application of this migration. After application, the fingerprint differed from the deployed reference in exactly one object: `public.complete_booking_session(uuid,uuid)`. It does not insert a payment or alter ledger amounts.

After applying the migration in isolation, `partial_status_exact_schema.sql` passed for four synthetic cases: rounded partial Open Time (125.00 total, 40.00 paid, 85.00 due, 75 billable minutes); unpaid minimum-duration Open Time (50.00, 30 minutes); fully paid fixed session (100.00); and a 120-minute maximum-duration cap (120.00). Each duplicate close returned the same classification, an unauthorized authenticated user was denied, `anon` had no execute grant, and the existing two payment rows plus 140.00 in shift ledger remained unchanged. The test ran inside a transaction and rolled back all its fixture rows. The migration also corrected an already completed booking with a stale `unpaid` flag on idempotent retry without changing collected money.

**Remaining release gates:** This fix does not resolve the reproduced `CASH_LEDGER_REQUIRES_CANONICAL_COLLECTION` conflict in `complete_booking_payment` or make Dashboard discount and collection atomic. Exact-schema concurrency, refund, cross-shift reconciliation, malformed ledger, Auth implementation parity and Mobile/Dashboard integration tests remain open. Keep this PR Draft and do not merge or deploy it until the wider financial invariants and client compatibility are verified. Production application additionally requires a recent restorable backup, recovery procedure and the owner's approval for the specific change.

# Feature comparison and operating modes

| Capability | PanCafe public claim | PlaySpot source reviewed | Evidence gap |
| --- | --- | --- | --- |
| Windows workstation control | Client/terminal management, restriction and Wake-on-LAN advertised | No verified deployed PlaySpot Windows agent | Never present lock/unlock as successful |
| Cashier sessions and tariffs | Timed/indefinite session and advanced tariffs advertised | Dashboard fixed/Open Time sessions and server RPCs exist | Exact-schema close and pilot concurrency unverified |
| Booking requests | No equivalent integration contract found | PlaySpot manual-approval workflow exists | External PanCafe inventory not guaranteed |
| Shifts, inventory, reports | Advertised on PanCafe pages | PlaySpot modules present in repositories | End-to-end finance/reconciliation not certified |
| PS4/PS5 | Tariff mention in vendor changelog | Logical PlaySpot room/session types | Console and monitor control unsupported |
| Offline | Local server/client design indicated | PlaySpot offline cashier contracts reviewed previously | Long disconnection/replay pilot pending |

Three PlaySpot modes should be explicit: **booking-only** (manual owner/cashier confirmation; incumbent system stays), **native operations** (PlaySpot is authoritative for supported cashier workflows), and **bridge** (only independently verified adapter capabilities). The three PanCafe users and one paper user in the four-interview sample prioritize low-friction coexistence; they do not establish a universal product requirement or vendor prevalence.

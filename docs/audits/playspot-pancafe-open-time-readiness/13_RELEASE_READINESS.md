# Release readiness

Android application ID is `com.playspot.client`; `pubspec.yaml` version is `1.0.0+1`; Gradle targets `flutter.targetSdkVersion` and declares compile SDK 37. Resolve the effective target in an AAB and check [Google's current target requirement](https://developer.android.com/google/play/requirements/target-sdk) for the actual publication date. Release signing requires local `key.properties`; no key was created or exposed. The compile-only build reached AAB packaging but ran out of disk, so no artifact was validated. Inspect a future signed AAB, native 16 KB support ([Android guidance](https://developer.android.com/guide/practices/page-sizes)), permissions, deep links, FCM, privacy/data safety, account deletion, reviewer access and payment classification. Eligible new personal Play accounts need the [closed-testing prerequisite](https://support.google.com/googleplay/android-developer/answer/14151465). The physical/digital payments boundary must be reviewed against [Play payments policy](https://support.google.com/googleplay/android-developer/answer/10281818). **Google Play release: BLOCKED.**

Dashboard web build is a compilation check only. `vercel.json` contains a catch-all SPA rewrite to `/index.html`. Read-only Vercel inspection found project `playspot-dashboard` and its Git integration automatically started a preview build for dashboard commit `d08b8900bcbf58ad588fd22249f54b3e77b3c34f` after branch push. That build was canceled while `BUILDING` because this task prohibits deployment; Vercel reported `CANCELED`. No production promotion was performed. Future branch pushes may start another preview automatically, so its behavior must be accounted for before pushing. Deployment environment/domain/HTTPS, OAuth redirect, role boundaries, storage, realtime recovery, error monitoring and rollback still require isolated staging checks. **Controlled dashboard release: BLOCKED** pending staging walkthrough and backend correctness. See [risk register](14_SECURITY_AND_RISK_REGISTER.md).

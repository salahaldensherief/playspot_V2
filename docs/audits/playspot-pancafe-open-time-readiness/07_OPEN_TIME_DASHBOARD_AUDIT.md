# Dashboard Open Time audit

**SOURCE REVIEWED / MOCK TESTED.** `open_time_session_dialog.dart`, policy configuration, dashboard start use case and server RPC call already existed. The dashboard sends the cashier request to `start_open_time_session`; it must not calculate an authoritative price locally. The new dialog exposes the configured mode (`same_hourly`, `custom_hourly`, `hourly_plus_percentage`), rate/multiplier, minimum, rounding and maximum as a preview, with server authority explicit. Active cards now use elapsed time and a pending-final-bill message.

The dashboard calls `complete_booking_session` for close; no current dashboard call to legacy `complete_open_time_session` was found. `complete_booking_session` in the observed production catalog reads `open_time_pricing_snapshot`. It does not by itself prove amount collected or full ledger correctness. A running estimate was deliberately omitted pending a server quote contract. Upcoming booking warnings, maximum enforcement, partial-payment UX, canteen reconciliation and shift/analytics presentation need exact-schema integration tests. See [pricing](08_OPEN_TIME_SERVER_PRICING.md) and [finance](09_SESSION_AND_FINANCE_INTEGRITY.md).

# Native operations simulator — 24 October 2026

Status: implemented and locally tested in an isolated branch. This is protocol evidence, not a deployable Windows agent, backend integration, or a physical control pilot.

The inspected architecture alternatives were cloud-only Dashboard, per-PC cloud agent, branch coordinator with per-PC agents, and vendor bridge. The branch coordinator was chosen for deterministic LAN ordering during internet loss, but only as an isolated simulator. Existing offline cashier code stays intact and financial authority remains with the backend. The simulator contains no price, payment, booking-completion or Windows-control operation.

Implementation: Ed25519 permit/device/coordinator messages; one-use hashed enrollment token bound to station, permit and epoch; typed ordered start/end commands; durable operation result before ACK; duplicate/lost-ACK recovery; signed heartbeat, disconnected/unknown state, audit events; JSON persistence; loopback-only HTTP adapter. The agent reports *simulated* observed state. A pending command makes station connectivity unknown until ACK and a fresh heartbeat.

## Follow-up hardening on Draft PR #81 (24 October 2026)

Implemented an issuer-signed writer generation lease in the single coordinator process. Permit authorization now runs inside the coordinator's serialized state mutation, so a queued command cannot cross a local writer takeover unnoticed. Takeover cancels pending operations, clears previously observed connectivity, and issues a signed per-device generation fence. The simulated agent rejects commands from previous writer generations, including replayed commands, and heartbeats carry the writer generation so an old observation cannot restore connectivity. Device revocation increments the pairing epoch, cancels pending commands, rejects new coordinator traffic, and can be delivered to the agent as a signed persistent notice. The loopback test adapter exposes signed writer activation and revocation endpoints; it remains test-only.

At implementation commit `a3f07ae0a7560651de9bbf51dd6ac4a8afca711b`, `npm run check` PASS and `npm test` PASS (9 tests), including two stations/two cashiers, simultaneous independent commands, stale writer rejection, writer expiry/recovery, signed revocation after restart, old heartbeat rejection, out-of-order ACKs, duplicate/lost ACK recovery, disconnect/reconnect, corrupt storage, and loopback transport. [Flutter CI run 40110388253](https://github.com/salahaldensherief/playspot_V2/actions/runs/40110388253) PASS: native simulator, Flutter quality (formatting, analysis, tests and Android release build), and backend fixtures. [Dart formatting review 40110388233](https://github.com/salahaldensherief/playspot_V2/actions/runs/40110388233) PASS. No real PC or financial state was changed.

**Residual boundary:** this is not distributed single-writer proof. The JSON store synchronizes one process only; two coordinator processes can race on stale state. An agent that is offline cannot learn revocation/takeover immediately and may execute a previously signed command until its at-most-30-second expiry. The test issuer is not bound to actual PlaySpot staff, shifts, or backend RLS. Cross-process durable locking/lease authority, authenticated transport, protected keys, real Windows observation, and exact-schema cloud reconciliation remain release blockers. Draft PR #81 must not be merged as a device-control feature.

## Shared local authority follow-up (24 October 2026)

The prior JSON coordinator state was replaced with a single local SQLite state row. Each mutation now begins an immediate SQLite transaction, reloads the latest state, verifies writer generation and permit, and commits the state and audit together. Read endpoints also load the shared state rather than a process-local snapshot. The simulated agent keeps its independent JSON journal. This is a deliberate simulation-only format change; earlier JSON coordinator files are not migrated.

`npm run check` PASS and `npm test` PASS (13 tests) on Node 24.13.0. New separate-process tests demonstrate: concurrent writer-generation contenders yield one winner; the losing writer cannot queue; two writers racing one operation ID yield one committed command; writer expiry and reassignment; stale command rejection after agent fencing; process death inside a write transaction rolls back its provisional audit; restart sees committed state; revocation from another process cancels pending work; a pre-revocation command can execute on a disconnected agent before notice arrives; delivered revocation rejects subsequent commands and heartbeats; a corrupt SQLite file fails closed; and two processes can initialize the same fresh store. The offline execution case is a **known limitation demonstrated by a passing test**, not a successful instant-revocation claim. Final commit and CI are pending.

Scope of the new guarantee: SQLite serializes processes sharing the same local file on one host. It does not provide a distributed lease across hosts or an authenticated staff identity. Node 24's `node:sqlite` is experimental. Real systems still require backend-issued authorization, device-protected keys, authenticated transport, bounded clock drift, a tested offline policy, physical observation, and exact-schema booking/shift reconciliation. This Draft PR remains non-deployable.

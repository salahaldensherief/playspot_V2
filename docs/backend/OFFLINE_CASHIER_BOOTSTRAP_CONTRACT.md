# Offline cashier bootstrap review contract

Status: the coordinated fixed-session protocol and bootstrap were deployed on 2026-10-04 in `supabase/migrations/20261004132112_coordinated_offline_cashier_protocol.sql`. The matching timestamp was read from hosted migration history after successful application. `supabase/repairs/offline_cashier_bootstrap.sql` remains a review source; do not apply it independently or replay the older source files automatically. Actual offline cashier presentation is still not enabled.

`bootstrap_offline_cashier(p_lounge_id uuid, p_device_id uuid, p_online boolean)` uses canonical active/unbanned Auth eligibility and the scoped `sessions_control` grant through `refresh_cashier_writer`, and independently requires `bookings.view` before releasing customer data. Menu products/stock are included only with `menu_view`; shift cash totals require `shifts_view_blind_cash`. Execute is granted only to `authenticated`; anonymous, service and Auth admin roles cannot directly call this client bootstrap or its private amount helper. It requires exactly one open shift belonging to the current actor. A failure rolls back a first writer claim and permit issuance. A different device cannot take over an existing writer.

The complete JSON response has protocol version 2, authority, coverage, own shift, UUID-keyed rooms/products/bookings and `complete=true`. One SQL statement gives the resource projection a consistent MVCC snapshot without introducing room-before-booking lock inversion. Cached availability includes retained bookings, noncancelled tournament reservations and unexpired/unreleased booking holds. Coverage begins at the current minute and ends at permit expiry. There is no truncation disguised as completeness: oversized responses fail.

Prices and paid amounts use exact integer minor units; fractional-cent or invalid financial amounts fail. Debt is retained for the current shift even outside the capacity window. Unsupported advanced room pricing stays visible, with offline command eligibility disabled. Open-time, discounted/extra-controller sessions, unsupported payment evidence and foreign-shift records cannot silently become ordinary fixed offline sessions. Shift cash totals are hidden unless the actual `shifts_view_blind_cash` grant permits them. This is a point-in-time projection; later inventory/price/resource changes still require reconciliation conflict handling.

Native PostgreSQL 17.11 passed **23** isolated bootstrap checks against the coordinated migration, with deployed room/session guards loaded. These include scope, own shift and duplicates, bans/inactivity, anonymous access, the exact execute grant matrix, separate booking/menu read permissions, revoked permission, heartbeat mode, device takeover, blind cash, tournament/hold capacity, unpaid debt, pricing eligibility, exact cents, timezone, microsecond timestamp conversion and transactional claim rollback. The canonical fixture deliberately simulates Supabase default system-role grants and verifies revocation across all 32 new private helpers and seven private tables. The hosted hold guard definition was inspected and matched the canonical hold migration; its actual function and trigger were loaded into the fixture. Reservation correctly preserves a conflict and operation sequence when another user's hold exists, and succeeds after that hold is released. Fixtures mirror the columns this contract uses but not every hosted trigger, notification or policy.

Reproduce: set `PLAYSPOT_NATIVE_PG_PORT=55439`, point `PLAYSPOT_ROOM_GUARD_SQL` to the current room invariant migration and run `node supabase/tests/offline_cashier_bootstrap.test.mjs`. The runtime accepts only the owned localhost fixture port and creates/drops disposable databases. Optional `PLAYSPOT_BOOTSTRAP_CONTRACT_EXPORT` writes a synthetic response to a specified client fixture path. Dashboard's `test/fixtures/offline_bootstrap_contract.json` was generated this way and is consumed by a Dart encrypted-persistence test; it contains only randomly generated fixture identifiers.

This fixture needs native PostgreSQL and `btree_gist`, as do the existing fixed-session concurrency suites. Running it without `PLAYSPOT_NATIVE_PG_PORT` uses the lighter PGlite runtime and fails because that extension is unavailable; no assertions were skipped to disguise this limitation. The repository's backend CI job already provisions PostgreSQL 17 and sets the native port for all contract suites.

The first new CI run exposed a fixture setup omission: its clean cluster lacked the `supabase_auth_admin` role referenced by the deployed room migration, whereas earlier local tests inherited that role from another review fixture. The shared native factory now creates this non-login role alongside `anon`, `authenticated` and `service_role`. Production grants and assertions were not weakened. A newly initialized local PostgreSQL 17.11 cluster then passed **all 21 backend contract suites**, including bootstrap and the financial, permission, Auth, KYC, stock, session and concurrency suites.

The coordinated migration also passed **54** fixed-session reconciliation checks, including actual competing PostgreSQL connections. An online row trigger must not wait for the lounge mutex while holding its booking/room lock: it returns retryable `55P03 / CASHIER_WRITER_BUSY_RETRY` instead. Offline lifecycle paths lock the booking before its room, matching existing online RPCs. This prevents a reverse-order deadlock without admitting an offline venue booking. The existing writer race tests assert immediate refusal and refusal again after the offline transition commits; inverse races still prove genuine lock waits.

After deployment, read-only hosted checks found zero assigned writers, issued permits, operations and cash receipts, zero internal execute-grant leaks, authenticated-only bootstrap, anonymous narrow availability access and unchanged legacy venue availability. The capacity exclusion now references `cashier_capacity_period`; existing history retains planned capacity unless explicitly reconciled. The migration uses one transaction with five-second lock and thirty-second statement timeouts. No hosted booking, order, receipt, inventory or shift was created for testing.

All 21 source contract suites also passed on the fresh native PostgreSQL cluster after these changes. Backend CI now additionally tests the actual deployed coordinated migration. Security advisors report the new private RLS tables without policies at INFO level; this is deliberate RPC-only storage with no client/system-role table grants. Remaining production work is the actual presentation/bootstrap lifecycle, availability adapters, conflict review and explicit writer reassignment. Open-time/advanced pricing remain outside this fixed-session protocol. The inspected hosted hold trigger enforces the hold mutation invariant; bootstrap also exposes that capacity to the local preview. Neither layer may silently bypass a valid hold.

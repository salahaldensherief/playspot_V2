# دليل PlaySpot للمبتدئ: المحاكاة على Windows وخطة مختبر MTTL‑W01

تاريخ الدليل: 21 أكتوبر 2026. اقرأ كلمة **منفّذ** أو **مخطط** بجانب كل جزء.
نجاح المحاكاة لا يعني أن المشترك الكهربائي الحقيقي اتصل أو اشتغل.

## 1. أهم قرار قبل البداية

عندك مشتركان LG U+ MTTL‑W01، في كل واحد أربع مخارج يمكن التحكم فيها نظريًا
كل على حدة. ملصق الجهاز يقول 60Hz، وأنت أوضحت أن الكهرباء المحلية 50Hz.
صفحة [LG U+ الرسمية](https://www.lguplus.com/smart-home/device/IOT1000005)
تذكر أيضًا 60Hz. لم نجد فيها اعتمادًا للعمل على 50Hz.

**لا توصل المشتركين بالكهرباء لهذه التجربة الآن، ولا توصل بهما أي حمل، ولا
تضغط زر إعادة الضبط، ولا تعمل Pairing أو تحديث Firmware.** يلزم تحقق من
الشركة المصنعة أو شخص مؤهل كهربائيًا يراجع النسخة الفعلية والمواصفات، ثم
موافقتك الصريحة على نطاق التجربة الحية. موافقتك على مراجعة الكود لا تعني
موافقتك على تشغيل الجهاز. لن يثبت برنامج كمبيوتر أن الجهاز آمن كهربائيًا.

المتاح الآن آمن من ناحية عدم الوصول للهاردوير: برنامج محاكاة في ذاكرة
الكمبيوتر، لا يفتح منافذ ولا يتصل بالشبكة أو Supabase أو أجهزة الصالة.
يمكن ترك المشتركين مفصولين طوال الخطوات التالية.

## 2. افهم الأسماء دون مصطلحات صعبة

| الاسم | معناه في حالتك |
|---|---|
| PlaySpot | التطبيق الذي يدير الصالة والحجوزات |
| Cloud API | واجهة رسمية يتيحها مورد برنامج الصالة للتكامل عبر الإنترنت |
| Local Agent أو Connector | برنامج على كمبيوتر الصالة، يربط واجهة محلية مسموحًا بها بخدمة PlaySpot |
| Hybrid | بعض العمليات عبر API وبعضها عبر Connector، مع تحديد المسؤول عن كل عملية |
| Hardware Adapter | جزء متخصص في موديل هاردوير معين؛ لا يقرر من يستحق حجزًا |
| Mock / Simulator | جهاز وهمي للاختبار؛ لا يمثل إثبات توافق أي جهاز حقيقي |
| Firmware | البرنامج الداخلي الموجود داخل المشترك الكهربائي |
| Pairing | تسجيل اتصال مسموح بين طرفين؛ ربط Windows بـPlaySpot يختلف عن إعداد Wi-Fi للمشترك |
| Channel | مخرج كهرباء واحد من أربعة، مرقّم 1 إلى 4 داخل الجهاز نفسه |
| Idempotency | تكرار نفس الطلب بنفس رقمه لا ينتج أثرًا ثانيًا |
| Unknown | لا نعرف النتيجة، وقد يكون الأمر نُفذ؛ لا تعني فشلًا يسمح بالتكرار العشوائي |

المسار المطلوب مستقبلاً:

```text
طلب اختبار من PlaySpot
  → خدمة أوامر Bridge
  → Connector على Windows
  → Adapter خاص بـ MTTL-W01
  → المشترك الأول أو المشترك الثاني
```

هذا المسار منفصل عن الحجز والدفع والجلسات والكاشير. تشغيل مخرج كهرباء لا
ينشئ حجزًا ولا يخصم مالًا، وانتهاء حجز لا يرسل أمر إطفاء من هذا المختبر.

## 3. ما الذي يعمل الآن فعلًا؟

| الجزء | الحالة الفعلية |
|---|---|
| استبيان جاهزية Bridge بالعربية والإنجليزية | موجود في فرع المراجعة، ومعطل افتراضيًا |
| حفظ إجابات الاستبيان | في مسودة المتصفح فقط؛ ليست طلب موافقة محفوظًا بالخادم |
| تصنيف API / Local / Hybrid | اقتراح إرشادي؛ جميع أعلام تفعيل الحجز والتحكم false |
| جهازان وهميان، أربعة مخارج لكل جهاز | منفّذ في المحاكاة |
| التكرار والانقطاع وفقد الرد وإلغاء الربط وسجل الاختبار | اختبارات وهمية منفّذة |
| Agent مثبت كخدمة Windows | غير منفّذ |
| ملف MSI أو EXE رسمي موقّع من PlaySpot | غير متاح |
| شاشة Pairing أو زر تشغيل أجهزة في Dashboard | مخطط؛ غير منفّذ بهذا العمل |
| Adapter يتصل فعلًا بـMTTL‑W01 | غير منفّذ |
| حفظ سجل الأوامر بعد إغلاق البرنامج | غير منفّذ في المحاكاة الحالية |
| توافق الجهازين على 50Hz | غير مثبت |

لا تبحث عن برنامج اسمه PlaySpot Agent على مواقع غير معروفة. لا يوجد رابط
مثبّت رسمي لهذا العمل، ولا صور شاشات حقيقية لبرنامج لم يُبنَ بعد.

## 4. ما الذي تثبته على Windows الآن؟

للمحاكاة فقط تحتاج Node.js، وتحتاج Git لو ستنزّل الفرع بنفسك. لا تحتاج Docker
أو Python أو Home Assistant أو Matter أو MQTT، ولا تحتاج أي بيانات Supabase.

1. افتح [صفحة تنزيل Node.js الرسمية](https://nodejs.org/en/download).
2. اختر Windows والإصدار الرئيسي 22 أو 24، وهما الإصداران المستهدفان لاختبارات
   هذا المختبر. اختبارات هذه المراجعة المحلية استعملت Node 24.13.0.
3. اختر حزمة Windows المناسبة لجهازك؛ لا تنزّل ملفًا من إعلان أو رابط رسالة.
4. شغّل مثبّت Node المعتاد. احتفظ بخيار إضافة Node إلى PATH إن ظهر.
5. إن احتجت Git، استعمل [صفحة Git الرسمية لـWindows](https://git-scm.com/downloads/win).
6. بعد التثبيت أغلق PowerShell وافتحه من جديد من قائمة Start.
7. اكتب الأوامر التالية كل أمر في سطر واضغط Enter:

```powershell
node --version
npm --version
git --version
```

ظهور رقم إصدار يعني أن البرنامج موجود. رسالة `not recognized` تعني غالبًا أن
نافذة PowerShell قديمة أو PATH لم يُحدّث. أعد فتح النافذة ثم راجع تثبيت البرنامج.
لا تغير ExecutionPolicy ولا تعطل Defender أو Firewall لحل هذه الرسالة.
اختبارات الهاردوير الوهمية نفسها لا تحتاج `npm install` لأن كودها يستخدم
مكتبات Node المدمجة فقط.

## 5. الحصول على نسخة الكود الصحيحة

هذه خطوات من فرع مراجعة، وليست تثبيت منتج. قد يكون المستودع خاصًا؛ استخدم
حساب GitHub المخوّل لديك. لا تلصق Token في الشات أو في عنوان المستودع.

افتح مجلدًا مخصصًا للتجارب داخل Documents. من PowerShell داخل ذلك المجلد:

```powershell
git clone --branch feature/bridge-hardware-lab-review-20261021 --single-branch https://github.com/salahaldensherief/playspot_V2.git playspot-hardware-lab
Set-Location playspot-hardware-lab
git branch --show-current
```

الأمر الأخير يجب أن يعرض اسم فرع المراجعة نفسه. إذا كان عندك نسخة من
المستودع تعمل عليها بالفعل، لا تستبدل ملفاتك ولا تغيّر الفرع قبل حفظ عملك.
استعمل نسخة منفصلة للمختبر. لو ظهرت `Filename too long` على Windows، يمكن
تفعيل `git config --global core.longpaths true` إذا كنت تريد تغيير إعداد Git
لكل نسخك، أو استعمال مسار مجلد أقصر. لا تحذف الملفات لحل الخطأ.

## 6. تشغيل الاختبار الوهمي خطوة بخطوة

تأكد أنك داخل المجلد الذي يحتوي `tools` و`docs`:

```powershell
Test-Path tools/hardware-lab/mock_hardware.test.mjs
node --test tools/hardware-lab/mock_hardware.test.mjs
```

يجب أن يعرض الأمر الأول `True`. يعرض الاختبار عدد الاختبارات الناجحة والفاشلة.
إذا وجدت `fail 0` فقد نجحت حالات المحاكاة في نسختك. لو ظهر فشل، لا تجرب
الهاردوير لتعويضه؛ احتفظ باسم الاختبار ورسالة الخطأ دون أسرار وأرسلها للمطور.

لمشاهدة مثال مقروء لجهازين وهميين:

```powershell
node tools/hardware-lab/demo.mjs
```

ستظهر عبارة `SIMULATION ONLY`، ثم أسماء `simulated-strip-1` و
`simulated-strip-2` وقنوات 1–4. سيغيّر المثال حالة قناة **في الذاكرة فقط**.
لن يفتح شاشة رسومية أو يطلب كلمة سر Wi-Fi أو يحاول اكتشاف جهاز حقيقي.
تفعيل `enabled:true` داخل المثال يفعّل خدمة المحاكاة فقط، ولا يفتح قدرة حقيقية
على الشبكة. لا يوجد اختيار يحولها إلى وضع هاردوير حي.

عند انتهاء الأمر ترجع علامة PowerShell. كل الحالات والسجلات الوهمية تضيع
عند خروج Node. عند إعادة التشغيل يبدأ المثال من جديد؛ هذا ليس اختبارًا
لاستعادة سجل أوامر دائم بعد تعطل Windows.

## 7. كيف تقرأ نتيجة المثال؟

| الحقل | معناه |
|---|---|
| simulated | true يعني أن النتيجة من المحاكاة |
| deviceId | اسم جهاز واحد؛ لا تستعمل اسم القناة وحده لتحديد الجهاز |
| channels | الأرقام الأربعة المسموح بها داخل هذا الجهاز |
| firmware | في المحاكاة SIMULATED-UNKNOWN؛ ليس إصدار جهازك |
| online | حالة الجهاز الوهمي؛ لا تدل على اتصال كهربائي حقيقي |
| state | on أو off عندما تكون القراءة معروفة، وunknown عند الانقطاع |
| revision | رقم نسخة الحالة الوهمية، يزداد مع تنفيذ طلب جديد |
| effects | عدد آثار الأوامر الوهمية، يساعد في اختبار عدم التكرار |
| confirmed | المحاكي أكد الحالة؛ لا يعني أن حملًا حقيقيًا يعمل |
| duplicate | نفس الطلب سبق التعامل معه، ولا يوجد أثر ثانٍ |
| expired | وقت صلاحية الطلب انتهى؛ لا يُرسل بعد ذلك تلقائيًا |
| offline | الجهاز غير متصل في المحاكاة؛ لا توجد إعادة تلقائية للأمر |
| unknown | النتيجة غير محسومة، وتحتاج مطابقة أو مراجعة |

إذا كان المخرج 1 في الجهاز الأول on، فهذا لا يعني أن المخرج 1 في الجهاز
الثاني on. المعرف الكامل هو الجهاز + رقم القناة، وليس رقم القناة وحده.

## 8. التحقق من شبكة Windows دون لمس المشتركين

هذه أوامر قراءة إعدادات الكمبيوتر فقط. يمكن تشغيلها الآن مع بقاء المشتركين
مفصولين. لا تتضمن مسح منافذ الأجهزة أو إرسال أي أمر إليها:

```powershell
Get-NetIPConfiguration
Get-NetConnectionProfile
netsh wlan show interfaces
```

في النتيجة، ابحث عن بطاقة الاتصال المستخدمة، وIPv4Address، وDefault Gateway.
عنوان مثل `192.168.x.x` أو `10.x.x.x` قد يكون عنوانًا داخليًا. لا تنشر تفاصيل
الشبكة كاملة على الإنترنت. الكمبيوتر المتصل بكابل Ethernet يمكنه مستقبلاً
الوصول إلى أجهزة Wi-Fi إذا سمح الراوتر بالشبكة الداخلية بينهما.

وجود راوتر يدعم 2.4GHz لا يثبت أن اسم الشبكة المختار يستخدم هذا التردد. راجع
صفحة إعدادات الراوتر أو اسأل المسؤول عن الشبكة. `netsh` يصف اتصال الكمبيوتر
الحالي، ولا يثبت قدرة جهاز مفصول على الاتصال. لا تغيّر إعدادات شبكة الصالة
العاملة لمجرد الاختبار. الأفضل إعداد SSID/VLAN خاص بالمختبر بواسطة المسؤول.

مستقبلاً يحتاج المشترك والـAdapter مسار LAN مسموحًا بينهما. شبكة Guest قد
تعزل العملاء عن بعضهم. لا تُلغِ العزل عن كل العملاء؛ اطلب قاعدة محددة بين
جهاز المختبر وكمبيوتره. احتفظ بعنوان Windows مستقر عبر DHCP reservation
بمساعدة مسؤول الراوتر. لا تستخدم عنوان الإنترنت العام مكان عنوان LAN.

## 9. كيف تعرف Firmware الجهازين الآن؟

ابدأ بدون كهرباء: دوّن من ملصق كل وحدة اسم الموديل ورقم النسخة إن وُجد
والرقم التسلسلي والتردد والجهد. سمّهما في ورقتك «الوحدة أ» و«الوحدة ب».
لا تفتح جسم الجهاز، ولا تفك أي مسمار، ولا تلمس اللوحة الداخلية.

لو لديك صور قديمة أو سجل من تطبيق رسمي كان مستخدمًا سابقًا، سجّل الإصدار
منه مع تاريخ المعلومة. عدم كتابة firmware على الملصق أمر ممكن؛ اكتب «غير
معروف»، ولا تستنتج أنه 1.0.66 لأن الاسم MTTL‑W01 مطابق.

المراجع البرمجية تقرأ الإصدار من رسالة تعريف عند اتصال الجهاز بالخادم
المحلي. هذه طريقة **مخططة لمرحلة حية معتمدة لاحقًا**، وليست خطوة تُنفذ الآن.
لا تثبّت Firmware بديلًا لكي تعرف الإصدار. إصدار التكامل في Home Assistant
ليس هو إصدار Firmware المشترك.

## 10. نوعان مختلفان من Pairing في الخطة المستقبلية

**ربط Windows بـPlaySpot — مخطط:** يدخل المالك أو المدير المخوّل، يختار
الصالة الصحيحة، ويحصل على تحدٍّ مؤقت لمرة واحدة. يظهر على الكمبيوتر اسم
الصالة والتثبيت وبصمة المفتاح ونطاق العمليات. يوافق الطرف المخوّل على نفس
البيانات. الخادم يصدر اعتمادًا قصير العمر خاصًا بالتثبيت والصالة، ويمكن
إلغاؤه. لا يوضع service_role على Windows. تُحمى المفاتيح بحماية Windows
المناسبة لحساب الخدمة، ولا تخزّن داخل ملف إعدادات مكشوف.

**إعداد Wi-Fi للمشترك — مخطط وموقوف الآن:** المراجع تصف شبكة إعداد مؤقتة
للجهاز، يُرسل خلالها اسم Wi-Fi وكلمة السر وعنوان الخادم المحلي. هذا يغيّر
إعدادات جهاز حقيقي ويستلزم تشغيله؛ لذلك لا نوفر هنا خطوات تشغيلية أو أزرارًا
أو سكربت إرسال. يلزم التحقق الكهربائي والموافقة ومراجعة أداة الإعداد أولًا.

ربط Windows بالخادم لا يثبت هوية المشترك. ومعرف MAC وحده ليس كلمة سر أو
هوية مشفّرة. يجب اعتماد كل وحدة محليًا، ومنع جهاز غير مسجل من أخذ مكانها.

## 11. ماذا تعني شاشات الاستبيان الموجودة؟

الاستبيان مخفي افتراضيًا. يستطيع المطور عرضه في نسخة اختبار بمتغير البناء
`PLAYSPOT_BRIDGE_PREVIEW=true`؛ ذلك لا يفعّل الحجوزات أو أي أوامر هاردوير.
لا تحتاج أنت تشغيل Flutter لتجربة محاكاة Node السابقة.

| السؤال | كيف تجيب؟ |
|---|---|
| مكان برنامج الإدارة الحالي | اختر Cloud أو Windows محلي أو جهاز آخر أو لا يوجد أو غير معروف |
| اسم البرنامج وإصداره | من Help/About أو وثائق المورد؛ لا تكتب أي سر |
| الإذن بالتكامل | هل لديك موافقة مناسبة؟ وجود API لا يعني موافقة تلقائية |
| دعم API وتوثيقها | أجب حسب وثائق رسمية، لا حسب تخمين مندوب مبيعات |
| الوصول إلى API | HTTPS عام أم داخل شبكة الصالة أم غير معلوم |
| واجهة محلية مسموحة | دعم رسمي أو تصريح واضح، وليس تعديل قاعدة بيانات المورد بالقوة |
| كمبيوتر Windows وإنترنت صادر | هل يوجد جهاز مناسب يبقى يعمل وقت الحاجة؟ يظهر حسب المسار |
| الحجز الإلكتروني | هل ترغب في حجز مستقبلي عبر PlaySpot؟ |
| التحكم في الجلسات | هل ترغب في بدء/تمديد/إنهاء جلسة عبر تكامل مصرح به؟ هذا مختلف عن كهرباء المخارج |
| قراءة الإشغال | هل يستطيع المورد إعطاء حالة حديثة؟ |
| تخصيص حجز بصورة ذرية | هل يمنع النظام حجزين لنفس الفترة فعليًا؟ القراءة وحدها لا تكفي |
| أوامر الجلسات عبر المحلي أو API | يظهر السؤال فقط عندما تطلب التحكم والقناة المعنية موجودة |
| إشعارات التغييرات | هل توجد Webhooks/أحداث؟ غير معروف إجابة مقبولة |

الحقول غير المناسبة تختفي وتُستبعد إجاباتها القديمة من الحساب. «مش عارف»
تظل غير معروفة، ولا تتحول إلى إذن. النتيجة «مرشح لمراجعة تقنية» لا تعني
«متصل». الإجابات محفوظة محليًا في المتصفح فقط؛ تغيير الجهاز أو مسح بيانات
المتصفح قد يفقدها. لا يوجد إرسال تقييم Bridge للخادم في هذه النسخة. إرسال
ملف الصالة وKYC يستمر بمساره الأصلي ولا يحمل إجابات التكامل.

## 12. الشاشات المستقبلية التي لم تُنفّذ بعد

هذه معاني مقترحة للمصمم والمطور، وليست وصفًا لصور أو منتج موجود:

| الشاشة المخططة | ما يجب أن توضحه |
|---|---|
| Welcome / Mode | وضع Mock ظاهر، والتحكم الحقيقي معطل |
| Select lounge | اسم الصالة والفرع، مع منع اختيار صالة خارج صلاحيتك |
| Pair connector | صلاحية الرمز والبصمة وما تسمح به الموافقة |
| Local devices | الوحدات المعتمدة فقط، مع firmware والحالة وآخر قراءة |
| Outlet mapping | اسم الوحدة ثم القناة 1–4؛ منع الخلط بين الوحدتين |
| Read-only verification | القراءة فقط، ولا أزرار تحكم قبل الموافقات |
| Commands | رقم الطلب والهدف والمهلة والنتيجة الفعلية، مع تعطيل التكرار |
| Audit | من طلب ماذا ومتى والنتيجة، دون مفاتيح أو كلمات سر |
| Disconnect / Revoke | الفرق بين قطع الاتصال مؤقتًا وسحب صلاحية التثبيت نهائيًا |

## 13. الأخطاء الشائعة والتصرف المناسب

| الرسالة | المعنى والتصرف |
|---|---|
| Cannot find module / path | تأكد أنك داخل جذر المستودع وأن اسم الملف مطابق؛ لا تشغّل ملفًا عشوائيًا |
| LAB_DISABLED | الخدمة الوهمية معطلة افتراضيًا؛ استخدم المثال الموثّق فقط |
| MOCK_ONLY | تم رفض Transport غير وهمي؛ هذا قيد مقصود في المرحلة الحالية |
| SCOPE_DENIED / DEVICE_SCOPE_DENIED | الصالة أو التثبيت أو الصلاحية لا تطابق الهدف؛ لا تتجاوز الرفض بتغيير الهوية عشوائيًا |
| INVALID_COMMAND | حقل أو قناة أو نوع طلب غير مسموح؛ القنوات 1–4 فقط |
| IDEMPOTENCY_CONFLICT | أُعيد رقم أمر قديم بمحتوى أو جهاز مختلف؛ راجع الطلب الأصلي |
| STALE_SEQUENCE / STALE_REVISION | أمر قديم أو مبني على حالة قديمة؛ اقرأ الحالة أولًا |
| RECONCILIATION_REQUIRED | نتيجة سابقة غير معروفة؛ لا تُرسل أوامر متضاربة |
| MANUAL_REVIEW_REQUIRED | القراءة لم تحسم الطلب؛ لا تعرضه ناجحًا |
| CONNECTOR_DISCONNECTED | الاتصال مقطوع؛ العودة لا تعيد الأوامر القديمة تلقائيًا |
| INSTALLATION_REVOKED | الصلاحية أُلغيت؛ إعادة الاتصال القديمة ممنوعة |
| fail أكبر من صفر في الاختبار | أرسل اسم الاختبار ورسالة الخطأ للمطور، ولا تستخدم أجهزة حقيقية |

مستقبلاً إذا لم يظهر جهاز حقيقي بعد تجربة قراءة مصرح بها، تحقق بالترتيب من
الصلاحيات الكهربائية والموافقة، ثم firmware، ثم عنوان الخادم، ثم قواعد LAN
وFirewall، ثم رسالة التعريف. لا تفتح المنفذ على الإنترنت ولا تعطّل الحماية
كلها كحل. لا تشغّل أدوات OTA أو Reset كخطوة تشخيص تلقائية.

## 14. الإيقاف وإلغاء الربط وإزالة البرنامج

**الآن:** الاختبارات والمثال تنتهيان تلقائيًا. إذا احتجت إيقاف أمر شغال في
PowerShell اضغط Ctrl+C. لا توجد خدمة Windows أو مهمة مجدولة أو منفذ يحتاج
إغلاقًا أنشأه هذا المختبر. توقف Node لا يطفئ مخارج فعلية، لأنه لم يتصل بها.
لإزالة المختبر، احتفظ بالتقرير والتعديلات التي تريدها ثم احذف مجلد النسخة
التجريبية يدويًا من File Explorer بعد التحقق من اسمه. لا تحذف نسخة مشروعك
الأساسية. إزالة Git أو Node اختيارية من Settings → Apps إذا لم تكن تحتاجهما
لأعمال أخرى. لا توجد أسرار أو ملفات pairing أنشأتها المحاكاة.

**مستقبلاً:** اسحب اعتماد التثبيت من Dashboard أولًا، أوقف خدمة Connector من
الواجهة الموثّقة، راجع الأوامر المعلقة، ثم استخدم uninstaller الموقّع، وأزل
قاعدة Firewall المحددة ومفاتيح التثبيت المحمية. هذه خطة قبول للمثبت القادم؛
لم نخترع اسم خدمة أو أمر `Stop-Service` لبرنامج غير موجود. إلغاء الربط يجب
ألا يغيّر الحجوزات أو المدفوعات أو يرسل أوامر إطفاء جماعية.

## 15. قبل الانتقال من الوهمي إلى الحقيقي

يلزم تقرير كهربائي/تأكيد مصنع، وتوثيق كل وحدة، واعتماد firmware، وموافقة
صريحة على تجربة حية محددة، وAdapter فعلي مُراجع، وشبكة معزولة، وتسجيل دائم
للأوامر، وصلاحيات ضيقة، وخطة إيقاف واستعادة. تكون البداية قراءة فقط. أي
تجربة مخارج أو أحمال تحتاج موافقة أخرى واضحة ونطاقًا يحدده المختص. لا
تستعمل نجاح اختبارات الكود كبديل لهذه المتطلبات.

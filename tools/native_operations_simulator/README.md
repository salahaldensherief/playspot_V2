# PlaySpot native operations protocol simulator

This is a disposable **local simulation**, not a deployable PC controller. It exercises a branch coordinator and a simulated station agent without Flutter, Supabase, Windows locking, or financial writes. The HTTP adapter binds to `127.0.0.1` on an ephemeral port for tests only; it has no production authentication or TLS layer. Never expose it to a network.

`Coordinator` verifies issuer-signed, short-lived venue/station/shift permits before enrollment and typed commands. An issuer-signed writer lease identifies one active cashier generation in a shared, local SQLite coordinator store. Every coordinator write uses `BEGIN IMMEDIATE`, reloads authoritative state, checks the permit/generation, and commits the command, cancellation, revocation or audit event as one transaction. This fences stale coordinator processes and avoids the former in-memory JSON split brain. Takeover cancels pending commands, invalidates prior heartbeats, and requires each agent to accept a signed generation fence before new commands. Enrollment uses a 256-bit, one-use token and an agent-signed proof. The coordinator signs ordered commands; the agent verifies identity, epoch, writer generation, sequence, expiry and expected state, then persists the result before returning a signed ACK. A lost ACK can be replayed by operation ID. Signed revocation fences a paired device after delivery; the coordinator immediately rejects its ACKs and heartbeats. Signed heartbeats report observed simulated state; missed heartbeats or pending commands render connectivity `unknown`. An ACK is a device-protocol result, **not** a financial receipt, canonical booking close, or proof of physical device control.

Run `npm ci`, `npm run check`, and `npm test` in this directory with Node 24. Tests use temporary local SQLite/JSON files, separate Node coordinator processes and loopback HTTP. No database credentials are needed. `node:sqlite` is experimental in the tested Node 24 runtime; the coordinator's previous JSON state file is not automatically migrated. This is safe for the disposable simulator only.

Trust boundaries and remaining risks: the simulator's permit issuer is generated inside tests and conveys no PlaySpot staff permission. SQLite enforces single-writer transactions only for coordinator processes sharing **the same local database file on one host**; it is not a distributed lease or cloud authority and has not been tested on network filesystems. An offline agent can execute an already signed, unexpired command before receiving a revocation or takeover fence; command validity is capped at 30 seconds, but real systems need a stricter, tested offline policy. The agent's JSON journal still lacks encryption and OS-protected keys. The loopback HTTP adapter exposes sensitive operations without network authentication and is test-only. Before any lab or production device use, implement backend-issued authorization and revocation, authenticated transport, protected private keys and journal, bounded clock drift, actual observed Windows state, signed updates and rollback, and cloud reconciliation against the exact booking/shift schema.

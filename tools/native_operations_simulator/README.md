# PlaySpot native operations protocol simulator

This is a disposable **local simulation**, not a deployable PC controller. It exercises a branch coordinator and a simulated station agent without Flutter, Supabase, Windows locking, or financial writes. The HTTP adapter binds to `127.0.0.1` on an ephemeral port for tests only; it has no production authentication or TLS layer. Never expose it to a network.

`Coordinator` verifies issuer-signed, short-lived venue/station/shift permits before enrollment and typed commands. An issuer-signed writer lease identifies one active cashier generation inside the **single coordinator process**. Takeover cancels pending commands, invalidates prior heartbeats, and requires each agent to accept a signed generation fence before new commands. Enrollment uses a 256-bit, one-use token and an agent-signed proof. The coordinator signs ordered commands; the agent verifies identity, epoch, writer generation, sequence, expiry and expected state, then persists the result before returning a signed ACK. A lost ACK can be replayed by operation ID. Signed revocation fences a paired device after delivery; the coordinator immediately rejects its ACKs and heartbeats. Signed heartbeats report observed simulated state; missed heartbeats or pending commands render connectivity `unknown`. An ACK is a device-protocol result, **not** a financial receipt, canonical booking close, or proof of physical device control.

Run `npm ci`, `npm run check`, and `npm test` in this directory. Tests use temporary local files and loopback HTTP. No database credentials are needed.

Trust boundaries and remaining risks: the simulator's permit issuer is generated inside tests and conveys no PlaySpot staff permission. The JSON store serializes changes only within one process; a second coordinator process can load stale state, so this **does not prove cross-process single-writer safety**. An offline agent can execute an already signed, unexpired command before receiving a revocation or takeover fence; command validity is capped at 30 seconds, but real systems need a stricter, tested offline policy. The loopback HTTP adapter exposes sensitive operations without network authentication and is test-only. Before any lab or production device use, implement backend-issued authorization and revocation, cross-process lease/fencing with durable locking, encrypted LAN transport, OS-protected private keys and journal, directory durability, bounded clock drift, actual observed Windows state, signed updates and rollback, and cloud reconciliation against the exact booking/shift schema.
